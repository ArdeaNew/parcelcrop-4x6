# 发布流程

## 准备

1. 更新项目与程序集版本、更新记录和受影响文档。
2. 确认组件锁定清单中的官方版本、下载地址、SHA-256 和许可证。
3. 确保工作树只包含本次改动，不含真实面单、凭据、个人路径或构建缓存。

## 构建和验证

```powershell
./scripts/package.ps1 -Version 2.2.2
```

发布前必须通过：

- Release 构建零错误；核心测试和真实 PDF 集成测试均通过。
- 便携包内存在可运行的 PDF 组件、必要配置及第三方许可。
- 完整对应源码归档的 SHA-256 与锁定清单一致。
- 解压到含中文和空格的新目录，使用随包组件导入合成 PDF、预览并导出。
- 组件缺失时显示完整原因；恢复后可在原队列重试。
- 检查裁切、旋转、尺寸/DPI、源文件保留与文件夹显示。
- 文档相对链接有效，源码包不带 `bin/`、`obj/` 或下载缓存。

桌面操作、真实回收站和打印设备的验收应分别记录；未执行的项目不能写为通过。

## 发布与核验

1. 通过 GitHub 官方 CLI/API 提交源码，检查相应提交的 CI 结果。
2. 为已验证提交创建版本标签和 Release。
3. 同时上传便携包、应用源码包、锁定版本的完整 MuPDF 源码归档和 SHA-256 清单。对应源码必须与二进制在同一 Release 免费下载。
4. 发行说明简述功能变化、修复、运行要求和验证结果，明确便携包已经包含 PDF 组件。
5. 从 Release 下载已上传文件，核对实际文件哈希、版本和标签提交。

MuPDF 源码必须使用官方完整 source.tar.gz，不能以缺少第三方子模块的自动生成源码 ZIP 替代。保留上游版权与许可材料，见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
