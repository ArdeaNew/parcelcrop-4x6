# 架构与行为合同

## 处理路径

```text
MainForm：选择 PDF、保存每个任务的裁切与方向
    ↓
PdfConverter：临时副本 + 源文件哈希 + 页数检查 + mutool 渲染
    ↓
PreparedPage：栅格图路径、页面尺寸、自动检测框
    ↓
ContentCrop / CropCanvas：检测、交互裁切、输出预览
    ↓
PdfConverter：核对源文件 → 裁切/旋转 → 等比合成 → 临时 JPEG
    ↓
验证 JPEG → 提交最终文件 → 通知 Windows Shell
    ↓
可选回收原 PDF → ConversionResult → 更新队列状态
```

## 职责

| 类型 | 职责 |
| --- | --- |
| `Program` | STA 入口和 WinForms 消息循环 |
| `MainForm` | 队列、异步预览、批处理、停止、关闭与状态显示 |
| `LabelJob` | 每个源文件的裁切、旋转、预览任务与完成状态 |
| `PreparedPage` | 临时目录、渲染图、哈希、尺寸及清理 |
| `PdfConverter` | 外部渲染器调用、源验证、图像合成与输出提交 |
| `RendererPathResolver` | 优先选择随包组件、处理配置回退并检查可执行文件格式 |
| `ShellNotifications` | 最终文件创建、删除和目录变化的 Windows Shell 通知 |
| `SafeRecycleBin` | 受控地请求回收原文件，避免退化为永久删除 |
| `ContentCrop` | 基于像素的边框/内容范围启发式检测 |
| `CropCanvas` | 源坐标与显示坐标映射、交互裁切、输出预览 |
| `ConversionResult` / `AppError` | 成功路径、回收结果、可读错误与警告 |
| `OutputSpec` | 1600×2400、400 DPI、24 px 边距的规格 |

## 关键设计

**输出比例与内容比例分离。** 从原栅格图截取合法区域，按 90° 步进旋转，以同一缩放系数适配画布内部区域，居中绘制并保留白底。交互裁切维持初始框比例，而输出画布始终为 2:3。预览使用缩略图，其像素清晰度不代表最终导出质量；过小的缩略图裁切应跳过预览，不能让 UI 定时器抛出异常。

**输入快照。** 准备阶段复制 PDF 并保存哈希，导出前重新核对源文件。如果外部程序改变了源内容，要求移除并重新加入，避免把旧预览结果当作新 PDF 的输出。

**可见的最终文件。** JPEG 先写在目标目录的独立临时路径；重新读取尺寸和 DPI 验证后才移动到最终文件名。拒绝覆盖已有输出，失败时清理本次临时文件。Windows Shell 文件/目录通知发生在最终 JPG 已提交并且文件句柄关闭之后，避免通知与实际文件就绪顺序相反。通知不能被当成网络盘、同步客户端或所有 Explorer 状态均正常的证明。

**源文件保留。** 默认不回收 PDF。仅在用户勾选、本次输出已成功提交时才尝试送入回收站。回收失败是“输出已保存但原文件保留”的警告，不能谎报整次导出失败或改为永久删除。

**异步和生命周期。** 外部渲染工作在后台执行，以共享门限串行化渲染，限制同时使用的内存。预览通过选择版本与任务状态避免迟到结果替换当前文件。批处理逐项执行，停止请求阻止后续任务；关闭窗口取消准备工作并在完成必要清理后退出。

**外部进程。** `mutool` 使用指定程序路径直接启动，不通过命令解释器。标准输出与标准错误都读取以免阻塞，单次调用设有超时；取消或超时时清理外部进程。渲染器与应用同为当前用户权限，并未隔离到安全沙箱。

**组件与重试。** 随包 `mutool.exe` 优先于环境变量；每次准备预览重新查找组件，允许修复文件后直接重试。启动前检查 PE 头以拒绝明显损坏或不兼容的程序；组件缺失、启动错误及 Windows 加载失败与 PDF 内容错误分开呈现。详情框可滚动复制，重试时重新创建已失败的准备任务，成功后清除旧错误状态。

**完整发行包。** 构建脚本按固定 SHA-256 恢复官方组件和完整对应源码，运行真实 PDF 测试，再检查解压后的组件可启动和渲染。便携包包含上游许可；对应源码归档与二进制放在同一 Release。
