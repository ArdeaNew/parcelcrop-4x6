# 自动化回归测试

`ParcelCrop.Tests` 是 Windows / .NET Framework 4.8 控制台测试程序。它直接引用应用项目，不依赖 xUnit、NUnit、MSTest 或其他 NuGet 测试库。全部测试成功返回 `0`；断言失败返回 `1`；命令行参数错误返回 `2`。

## 构建与运行

先安装仓库要求的 .NET SDK 和 .NET Framework 4.8 Developer Pack，在仓库根目录运行：

```powershell
dotnet build tests/ParcelCrop.Tests/ParcelCrop.Tests.csproj -c Release
& ./tests/ParcelCrop.Tests/bin/Release/net48/ParcelCrop.Tests.exe
```

首次构建仍需生成 SDK 的还原元数据，但项目没有第三方测试包需要下载。已完成还原时可使用 `dotnet build --no-restore`。

默认运行 **61 项测试**，并明确标记跳过 4 项真实 MuPDF 集成测试。默认进程测试把测试程序本身当作可预测的模拟渲染器，不需要安装 `mutool.exe`。

若已有从可信来源取得的 MuPDF，可显式启用真实渲染器测试：

```powershell
& ./tests/ParcelCrop.Tests/bin/Release/net48/ParcelCrop.Tests.exe --renderer 'C:\Tools\MuPDF\mutool.exe'
```

这会运行全部 **65 项测试**。`scripts/package.ps1` 会恢复锁定的官方组件并执行全部测试；发布和 CI 不接受跳过真实 PDF 集成测试。`--help` 显示简短用法。

## 测试数据与边界

- 每项测试在系统临时目录 `ParcelCrop.Tests/<随机标识>` 中创建独立夹具，结束时清理自己的目录。
- PDF 夹具由代码生成，包含有效交叉引用偏移；无需 PDF 库或真实客户标签。
- 回收测试注入替代回调，仅删除本测试生成的文件，不调用真实回收站。COM 测试仅获取接口指针，不执行 Shell 文件操作。
- 窗口生命周期测试运行不可见、无任务栏条目的窗体消息循环；鼠标捕获测试直接调用本程序的事件方法，不向用户桌面注入输入。
- 模拟渲染器测试用于验证进程控制；真实 PDF 兼容性必须通过 `--renderer` 运行，不能用模拟结果代替。
- 本套件不声称覆盖资源管理器实际刷新、图形界面的全部交互、真实回收站策略或所有 PDF 编码。相关行为仍需人工验收。
- 进程取消测试有 5 秒启动/退出容限；若在负载极高的机器失败，应先查看该项错误和进程状态。

## 添加测试

在相应 `Register` 方法中添加独立测试，使用 `Check` 断言。所有夹具放入 `TempCase`，使用 `using` 释放图片与预览资源。转换成功路径应保留默认 `recycleSource: false`；测试回收流程时必须注入 `recycleFile`，不要操作真实文件或真实回收站。
